<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor input -> Web3Forms | Untrusted name/email/message cross to a third-party service over HTTPS |
| Web3Forms response -> DOM | Third-party response rendered to the page |
| bots -> form | Automated spam submissions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-08 | Tampering | Spam/bot floods | mitigate | Hidden botcheck honeypot checkbox filtered by Web3Forms; required + type=email validation. hCaptcha deliberately not added (adds third-party script on mobile, outside D-09 spirit); revisit if spam volume warrants |
| T-03-09 | Tampering/XSS | Result messages in DOM | mitigate | Messages come from the data file and are written with textContent; Web3Forms response text is never inserted into the DOM |
| T-03-10 | Repudiation/Availability | Silent form failure with placeholder key | mitigate | isPlaceholderKey guard: fieldset disabled + visible role=alert notice with call/email links; script refuses to submit |
| T-03-11 | Information Disclosure | Access key in client HTML | accept | Web3Forms access keys are designed to be public; abuse limited by Web3Forms domain/rate controls; documented |
| T-03-12 | Information Disclosure | PII in transit | mitigate | Action and fetch URL are https only; no client-side storage of input |
| T-03-13 | Spoofing | Open redirect via redirect field | mitigate | redirect value comes only from the build-time data file, never from visitor input |
</threat_model>
